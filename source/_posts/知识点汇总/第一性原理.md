# 第一性原理

## 一句话概括

**把事物拆到最底层、最不可再分的事实，然后从那里往上推。**

不依赖类比，不依赖"别人怎么做"，只依赖最基本的事实和逻辑。

---

## 为什么需要它？

人天生爱走捷径。面对新问题，大脑的第一反应不是"这事儿本质是什么"，而是"别人怎么干的"——

- 别人做手机用塑料外壳 → 我也用塑料外壳
- 别人做火箭外包采购 → 我也外包采购
- 别人学编程先看框架 → 我也先看框架

这叫**类比思维**（reasoning by analogy）。它快、省力、大多数时候够用。但有一个致命缺陷：

> **你很难实现颠覆式突破，只能做到渐进改良。**

第一性原理就是类比思维的解药。它逼你放弃"别人怎么做"，回到"这事儿到底怎么回事"。

---

## 它到底是什么？

拆开来看：

### 1. "第一性"——最底层的、不可再推的

数学里的公理就是第一性：**（在欧几里得几何中）两点之间直线最短**，你没法再往下证明了，它就是起点。

物理学里的基本定律也是：F = ma，这不是推导出来的，是观察总结的，然后从它推导出一切力学结论。

**第一性 = 你再往下拆，就拆不动了。**

### 2. "原理"——从底层事实出发，一步步推导

不是拍脑袋，不是抄作业，而是：

> **事实 → 逻辑 → 结论**

每一步都站得住脚，没有"因为别人这么做所以我也这么做"。

### 3. 合起来

**第一性原理 = 找到最基本的事实，从事实出发，用逻辑推导，得到结论。**

---

## 怎么用？三步法

### 第一步：识别并拆解

把你面对的问题里所有的"假设"和"惯例"列出来，然后一个个追问：**这是事实，还是只是"大家都这么做"？**

举例：造火箭

| 常规认知 | 追问 |
|---|---|
| 火箭很贵，一次几亿美元 | 为什么贵？ |
| 因为材料贵 | 材料到底值多少钱？ |
| 铝合金、碳纤维、钛合金… | 铝的原料价多少？碳纤维呢？ |
| … | 原材料成本其实只占约2%！ |

拆到最后发现：**火箭的"贵"不是物理必然，是行业惯例。**（据马斯克估算，火箭原材料成本约为成品价格的2%左右）

### 第二步：找到底层事实

把拆出来的东西分两类：

- **事实**：有数据支撑、可验证的（铝的市场价、碳纤维的强度、轨道力学公式）
- **假设**：只是"一直这样"的（火箭只能一次性使用、只能外包采购）

**保留事实，扔掉假设。**

### 第三步：从事实重新推导

用保留下来的底层事实，重新构建方案：

> 原材料成本只占约2% → 如果我自己造，成本可以接近原材料价 → 可回收复用 → 单次发射成本有望大幅下降（Falcon 9 已实现约1/10，星舰目标更低）

这就是 SpaceX 的逻辑。不是"别人怎么做我也怎么做"，而是"物理定律允许什么，我就做什么"。

## 生活中的例子

### 做菜

- **类比思维**：照着菜谱做，1克盐、2克糖，照抄
- **第一性原理**：盐的作用是提供咸味、糖的作用是平衡酸味和提鲜 → 按自己口味调整 → 你做的菜比菜谱更适合你自己

### 学编程

- **类比思维**：别人学 Java 我也学 Java，别人刷 LeetCode 我也刷 LeetCode
- **第一性原理**：编程的本质是什么？→ 用指令控制计算机解决问题 → 我要解决什么问题？→ 需要哪些工具？→ 学那些工具

### 买房

- **类比思维**：大家都买学区房 → 我也买
- **第一性原理**：我买房的核心需求是什么？→ 住得舒服 + 通勤合理 + 预算可控 → 按这三个条件筛选，而不是跟着人群跑

## 第一性原理 vs 类比思维

| | 类比思维 | 第一性原理 |
|---|---|---|
| **起点** | 别人怎么做 | 事实是什么 |
| **过程** | 模仿 + 微调 | 拆解 + 重建 |
| **结果** | 渐进式改进 | 可能颠覆式创新 |
| **速度** | 快 | 慢 |
| **适用场景** | 成熟领域、时间紧迫 | 新领域、需要突破 |

两者不是对立的。**大多数时候用类比思维就够了**——你不需要每次做饭都从分子运动论推导。但在关键决策、创新突破、或者"感觉哪里不对但说不清"的时候，第一性原理是那把手术刀。

---

## 常见误区

### ❌ 误区一：第一性原理 = 什么都从头想

不是。你不需要从量子力学推导怎么煮鸡蛋。**第一性原理是工具，不是宗教。** 该用的时候用，该抄作业的时候抄。

### ❌ 误区二：只有天才才能用

马斯克把它带火了，但这个方法不神秘。任何人面对任何问题都可以问一句："这是事实，还是只是惯例？"——这就是第一性原理的起点。

### ❌ 误区三：拆到底就一定能创新

拆解只是第一步。拆完之后你得**重新组合**，而且组合出来的方案得**行得通**。拆而不建，只是拆了。

---

## 它的代价

第一性原理不是万能的，用错了比不用还糟：

- **费时费力**：拆解和验证需要大量时间和领域知识，日常小事不值得
- **过度拆解**：容易陷入"分析瘫痪"，拆得太细反而无法行动
- **知识门槛**：没有足够的领域知识，你连"事实"和"假设"都分不清——外行拆火箭，拆出来的全是错的
- **忽略隐性约束**：法规、安全标准、供应链现实……这些"惯例"背后往往有硬约束，盲目推翻会翻车

**什么时候该用？** 高 stakes 决策、创新瓶颈、行业惯例明显不合理时。**什么时候别用？** 日常小事、时间紧迫、你对领域一知半解时。

## 一张图总结

```
问题
  │
  ▼
识别所有"假设"和"惯例"
  │
  ▼
逐个追问：这是事实吗？
  │
  ├─ 是 → 保留（底层事实）
  └─ 不是 → 质疑并验证（可能是过时惯例，也可能有隐含合理性）
  │
  ▼
从保留下的事实出发
  │
  ▼
用逻辑一步步推导
  │
  ▼
得到全新方案
```

## 谁在用？

- **埃隆·马斯克**：SpaceX（火箭成本拆解）、Tesla（电池成本拆解）
- **亚里士多德**：最早提出这个概念——"在每一系统的探索中，存在第一性原理，即最基本的命题，不能被违背或删除"（大意）
- **笛卡尔**：怀疑一切，只保留不可怀疑的——方法论上的第一性原理
- **费曼**："我不能创造的东西，我就不能真正理解"——理解到最底层才能重建

---

## 最后一句

**第一性原理不是让你否定一切经验，而是让你分清：哪些是铁打的事实，哪些只是"一直这样"。**

对事实尊重，对惯例怀疑。这就是全部。
