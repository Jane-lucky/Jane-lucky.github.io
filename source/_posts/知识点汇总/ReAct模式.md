# ReAct 模式：让模型「边想边做」

## 一句话概括

**把「回答问题」拆成「思考→行动→观察」的循环，让模型的每个判断都建立在真实证据上，而不是空转在先验里。**

> 本文同时用了两套思维模型来审视它：先从《第一性原理》拆解「为什么必须长这样」，再用《对抗式审查》站到对立面拆穿它的每个卖点。建议配合那两篇一起读。

## 第一性原理：为什么要「行动」

现代大模型有个很别扭的处境：它记下了海量知识，但它**无法验证其中任何一句话**。

- 它只是一个「预测下一个词」的概率机器，不是数据库，也不是搜索引擎；
- 知识全部冻结在训练那一刻——世界在变，它会过期；
- 遇到长尾问题，几乎没人写过正确答案；
- 最要命的是，它**分不清「我确实知道」和「我在编」**——两种状态的「表面确信度」一模一样。

这就是幻觉的根源：**无法接触现实的东西，只能用先验去猜。**

由此推出第一性原理的第一个结论：**纯靠「思考」，永远够不到训练分布之外的真相。想对答案负责，就必须让模型「行动」——对外获取证据。**

## 那「思考」是不是就废了？

既然行动能拿到真相，直接猛调工具不就好了？同样是坑：

- **行动昂贵**——每次工具调用都要时间、token、外部服务成本；
- **行动稀疏**——你不可能把一切可能性都查一遍；
- **行动有前置条件**——很多查证必须先知道「该查什么」，这本身就是推理。

所以第二层推出：**如果只有行动没有思考，模型就是无头苍蝇。** 得有一个调度策略决定「何时想、想什么、何时动手、何时停」——这个策略，就是「思考」。

## 重新建模：把「回答问题」当成一次决策

一次问答其实是一个**受限的序贯决策问题**：

```text
状态 s  ：目前手上已收集到的全部信息（问题 + 历史结果）
动作 a  ：要么「再推理一步」，要么「调用某个工具」
转移    ：行动后拿到新观察，状态随之更新
目标    ：期望正确性尽量高，代价（步数）尽量小
```

此时模型一人分饰两角：**策略网络**（决定想还是做）+ **工作记忆/局部世界模型**（把观察折叠进上下文）。「推理」的本质是**有计划地消化证据**。

## 为什么必须「边想边做」，而不是「想完再做」

最硬的一条约束：**只要目标是「用证据修正判断」，思考就必须发生在「有证据之后」。**

- 想完再做 → 想法全建立在「我以为会拿到什么」的假设上，未经检验，一步带偏全程；
- 只做不想 → 无头苍蝇。

所以要**交替**：每次「想」都站在上一步真实观测的事实上。这一条——**反馈是否真正回流进决策**——正是 ReAct 和普通「思维链 + 插件」最本质的分野。它的灵魂不在工具，而在那个**闭环**。

于是自己推出一份 ReAct 定义：

> **ReAct = 把「回答问题」建模成序贯决策，用带预算的推理引导稀缺的外部证据采集，在每次真实观测后闭环修正——让「判断」盯死在「证据」上，而非「先验」里。**

## 对立面 1：ReAct 只是把「病」挪了地方

- **工具不是真理，只是另一类输入。** 网页可能是错的、过时的、互相矛盾的；
- 模型的本质是**照单全收**——大量实验证实 *sycophancy*：模型对工具结果几乎不设防（recency、锚定）。

所以：**ReAct 没有消除幻觉，它只是把「凭记忆编答案」换成「轻信工具」。** 越多的步骤，越容易把错误包装成一本正经的推理。

## 对立面 2：推理痕迹 ≠ 行为原因

ReAct 的卖点是**可解释**（每步 Thought 可回看）。但它很可能是**事后合理化**——先蒙对答案，再倒编一条合理的路径。

**一条漂亮的 Thought，只证明「叙述能力强」，不证明「答案是对的」。** 判对错得靠外部验证，别把 Thought 当执行根因。

## 对立面 3：成本黑洞

- Token：纯推理一次；ReAct 每步一次模型+工具往返，随步骤线性膨胀；
- 延迟：串行等待，慢一大截；
- 失败成本：每一步都可能踩雷，**一步错步步错**。

对简单问答，ReAct 是**负收益**——只有「必须外部信息 + 多步骤」的任务才值回票价。

## 对立面 4：骨架里没有「刹车」和「护栏」

- **没有终止机制**——反复行动拿不到结果会空转，全靠外层最大步数硬切，暴力切完输出半成品；
- **没有沙箱/白名单**——一步即兴行动可能误触删除、支付、外发等危险能力。**安全边界全靠外部硬补，不是这个范式自带的。**

## 最刺耳的一条：增益在快速缩水

**跟最强基线比，别跟烂基线比。** ReAct 原始论文是在当时偏弱的模型上跑的；换到 GPT-4 这一代后，**一张更好的 prompt 或更壮的底座就能大幅追平甚至反超 ReAct**。

翻译：**ReAct 的一部分「聪明」是在替当时的笨模型还债**，不是不可替代的真本事，更接近一个「谁都能用、先到先得」的脚手架。

## 一句话戳穿本质

> **它解决的是「让模型获取外部证据、修正判断」的编排问题，而不是「如何正确判断」本身。**

推理准不准、工具可信不可信、世界真不真——**ReAct 一概不管**。它是 `抓证据 + 闭环修正` 的优化壳，不是认知内核。真正决定上限的，永远是最底层模型的判断力 + 工具的可靠性 + 外部护栏的严不严。

## 结论：必要，但不充分

- **第一性原理**告诉我们：为什么闭环采集证据不可绕过——真相不写在参数里；
- **《对抗式审查》**告诉我们：闭环是**必要**的，却**远不是充分**的——难在工具信任、终止策略、误差累积、批判性校验。

对 ReAct 的公正好评，不是「它很聪明」，而是「它把一套必须的骨架，第一次高效又通用地装进了 LLM」。当它是「聪明」就高估了它；当它是「骨架」就恰如其分。

收束成一句话：

> **ReAct 不是一个答案，而是一套「带着预算去跟世界对话」的协议。它动不动脑、安不安全、值不值钱，取决于和它对话的模型、工具、以及外部的护栏——从来不是协议本身。**
