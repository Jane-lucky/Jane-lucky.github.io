# RAG

## 一句话概括

**大模型记不住所有东西，所以在回答之前，先从外部知识库里把相关内容找出来，喂给它，再让它回答——这就是 RAG。**

---

## 为什么需要它？

回到一个底层事实：**大模型的知识是静态的、有限的、会过时的。**

拆开看三个硬限制：

### 1. 训练数据有截止日期

大模型的知识来自训练数据，训练完成的那一刻，它的知识就冻结了。

- GPT-4 的训练数据有截止日期 → 截止之后发生的事它不知道
- 你问"最新的 iPhone 是哪款" → 它可能回答 iPhone 15，因为训练时 iPhone 16 还没发布

**模型不会自己上网查资料。** 它只知道训练时见过的东西。

### 2. 训练数据没有你的私有信息

- 你们公司的内部文档、业务规则、代码仓库
- 你个人的笔记、邮件、聊天记录
- 特定领域的专有知识（医疗病例、法律判例、金融数据）

**这些从来没进过训练集，模型根本不知道它们存在。**

### 3. 模型会"幻觉"（Hallucination）

当模型不知道答案但又被要求回答时，它不会说"我不知道"——它会**编一个看起来合理但实际错误的答案**。

- 问一个不存在的 API 用法 → 它会编一个看起来很像真的接口文档
- 问一个过时的政策 → 它会用旧知识拼凑，可能和现行政策矛盾

**模型天生倾向于"回答"而不是"承认不知道"。**

---

这三个限制加起来，意味着：**如果你让大模型直接回答事实性问题，你永远不知道它是在回忆训练数据、还是在编。**

RAG 就是解决这个问题的。

---

## 它到底是什么？

从第一性原理拆开：

### R = Retrieval（检索）

在模型回答之前，**先从外部知识库中找到和问题相关的信息**。

这一步的本质是：**把"模型需要知道什么"和"模型已经知道什么"之间的差距，用外部数据补上。**

### A = Augmented（增强）

把检索到的信息**拼接到模型的输入中**，作为回答的依据。

模型现在不仅有自己的训练知识，还有你刚刚喂给它的最新、最相关的信息。它的回答质量因此"增强"了。

### G = Generation（生成）

模型基于增强后的输入，**生成最终回答**。

关键区别：
- **没有 RAG**：模型只靠训练数据生成 → 可能过时、可能幻觉
- **有 RAG**：模型基于检索到的事实生成 → 有据可依、可溯源

### 合起来

**RAG = 先检索相关信息，再增强输入，最后生成回答。让大模型的输出从"凭记忆编"变成"有据可依"。**

---

## 怎么做？四步法

### 第一步：建知识库（Indexing）

把你的文档、数据变成可检索的格式：

```
原始文档
  │
  ▼
切分成小块（Chunking）
  │  "一篇100页的文档" → 切成200个段落块
  │
  ▼
向量化（Embedding）
  │  每个块 → 一个高维向量（如1536维）
  │  语义相近的文本 → 向量距离近
  │
  ▼
存入向量数据库
     Chroma / Pinecone / Milvus / Weaviate ...
```

**为什么需要向量化？** 因为"语义相似"不能用关键词匹配——"如何退款"和"退货流程"字面不同但语义相关，向量能捕捉这种关系。

### 第二步：检索（Retrieval）

用户提问时，从知识库中找最相关的内容：

```
用户问题："公司的差旅报销标准是什么？"
  │
  ▼
问题向量化（同一个 Embedding 模型）
  │
  ▼
在向量数据库中做相似度搜索
  │  找到 Top-K 个最相似的文档块
  │  K 通常取 3~10
  │
  ▼
返回检索结果
     "差旅报销标准：国内出差每日住宿上限500元..."
     "交通补贴：高铁二等座实报实销..."
     "审批流程：单次出差超过3天需部门经理审批..."
```

### 第三步：增强（Augmentation）

把检索结果拼接到提示词中：

```
给模型的输入：

【参考信息】
1. 差旅报销标准：国内出差每日住宿上限500元...
2. 交通补贴：高铁二等座实报实销...
3. 审批流程：单次出差超过3天需部门经理审批...

【用户问题】
公司的差旅报销标准是什么？

请基于参考信息回答，如果参考信息中没有相关内容，请说明。
```

**关键：告诉模型"基于参考信息回答"——这能降低幻觉率，但不是银弹。模型并不总是遵守指令，特别是当参考信息和它的训练知识冲突时，它可能选择忽略参考信息。**

### 第四步：生成（Generation）

模型基于增强后的输入生成回答：

> 根据公司规定，差旅报销标准如下：
> - 住宿：国内出差每日上限500元
> - 交通：高铁二等座实报实销
> - 审批：单次出差超过3天需部门经理审批

回答有据可依，每个点都能追溯到知识库中的原文。

## RAG vs 微调（Fine-tuning）

这是最常见的对比，很多人搞混：

| | RAG | 微调 |
|---|---|---|
| **做什么** | 给模型喂外部信息 | 改模型的内部权重 |
| **知识来源** | 外部知识库（实时可更新） | 训练数据（更新需重新训练） |
| **适合场景** | 事实性问答、知识查询 | 风格模仿、格式遵循、领域语感 |
| **更新成本** | 低（改知识库就行） | 高（重新训练） |
| **可溯源** | ✅ 能追溯到原文 | ❌ 知识融进了权重，无法溯源 |
| **幻觉控制** | 好（有依据才回答） | 一般（还是会编） |
| **成本** | 中（向量数据库+检索） | 高（GPU训练费用） |

**简单判断：**
- 需要"知道最新信息" → RAG
- 需要"用特定风格说话" → 微调
- 两者都要 → RAG + 微调（不冲突）

## 检索策略：不是搜到就行

检索质量直接决定 RAG 的效果。搜到垃圾，模型就基于垃圾回答——Garbage In, Garbage Out。

### 基础：向量相似度搜索

用余弦相似度找最接近的文档块。简单有效，但有盲区：

- **语义模糊**："苹果"是水果还是公司？向量分不清
- **长尾问题**：冷门问题在知识库中匹配度低，可能搜不到
- **多跳推理**："A公司的CEO之前在哪家公司？"需要先找CEO是谁，再找他的履历——单次检索搞不定

### 进阶策略

| 策略 | 原理 | 解决什么问题 |
|---|---|---|
| **混合检索** | 向量搜索 + 关键词搜索（BM25），取交集或融合 | 向量搜不准时，关键词兜底 |
| **重排序（Reranking）** | 先粗检索Top-50，再用交叉编码器精排Top-5 | 粗检索有噪音，精排提质量 |
| **查询改写** | 把用户问题改写成更适合检索的形式 | 用户问得太口语化，检索效果差 |
| **多跳检索** | 先搜一次，根据结果生成新查询，再搜 | 需要串联多个知识片段的问题 |
| **元数据过滤** | 按时间、来源、类别等过滤后再检索 | 缩小搜索范围，提高精度 |

## 常见误区

### ❌ 误区一：RAG = 接搜索引擎

不是。搜索引擎返回的是网页链接，你还得自己看；RAG 返回的是**结构化的文本片段**，直接喂给模型用。而且 RAG 的知识库是你自己的数据，不是全网。

### ❌ 误区二：RAG 能完全消除幻觉

不能。RAG 大幅降低幻觉率，但不能归零——模型仍然可能：
- 误解检索到的信息
- 检索结果本身有错
- 检索没找到相关内容，模型还是靠自己的"记忆"编

### ❌ 误区三：检索到的越多越好

不是。塞太多无关信息会**稀释有效信息的权重**，模型反而被干扰。Top-3~5 通常比 Top-20 效果好。质量 > 数量。

### ❌ 误区四：RAG 和微调是二选一

不是。它们解决不同问题，可以叠加——微调让模型学会"用公司风格说话"，RAG 让它"基于公司最新数据回答"。

## 它的代价

- **知识库维护成本**：数据更新了要重新索引，文档格式变了要重新切分，这是一个持续运营的工作
- **检索延迟**：每次问答多了一步检索，响应时间从 ~1s 变成 ~2-3s
- **切分策略难调**：这是 RAG 实践中最头疼的问题。块太大 → 检索不精准，噪音多；块太小 → 丢失上下文，语义不完整。常见策略：
  - 按固定长度切（简单但粗暴，可能切断句子）
  - 按语义段落切（质量高但实现复杂）
  - 按文档结构切（按标题/章节，保留逻辑完整性）
  - 没有万能参数，得根据数据特点反复调
- **向量数据库成本**：存储和检索都要资源，数据量大时成本不低
- **Embedding 模型选择**：向量化质量直接决定检索效果。不同模型差异很大——OpenAI 的 text-embedding-3-small 便宜但精度一般，text-embedding-3-large 精度高但贵；开源的 bge-large、gte-multilingual 在中文场景表现不错。选错 Embedding 模型，后面全白搭
- **检索质量瓶颈**：如果知识库本身质量差、覆盖不全，RAG 的天花板就在那里——再好的检索策略也搜不到不存在的东西

**什么时候该用？** 需要基于特定知识回答、知识频繁更新、需要可溯源的场景。**什么时候别用？** 创意写作、闲聊、通用知识问答——这些不需要外部知识库。

## 谁在用？

- **企业知识问答**：内部文档、规章制度、产品手册的智能问答
- **客服系统**：基于产品FAQ和工单历史回答用户问题
- **法律辅助**：基于法规和判例回答法律咨询
- **医疗辅助**：基于医学文献和临床指南辅助诊断
- **代码助手**：基于项目代码库和文档回答开发问题（如 Cursor、Copilot Chat）
- **研究助手**：基于论文库回答学术问题

---

## 最后一句

**RAG 的本质不是让模型变聪明，而是让模型在回答之前先查资料——就像开卷考试比闭卷考试靠谱，不是因为学生变聪明了，而是因为答案就在手边。**

但注意：开卷考试也可能抄错——如果检索到的资料本身有错，模型会更有信心地输出错误答案，这比"我不知道"更危险。**RAG 的可靠性 = 检索质量 × 模型遵从度**，两个因子都要关注。

关键不在模型有多强，在于你喂给它的资料有多准。
